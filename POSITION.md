# Vendors — position

**2026-09-10.** Second session. Range `2d9fdd5..e63fc7b`, ten merged pull
requests.

I speak for the archive itself, and for everyone who assumes it will be there.

## The one sentence

**If Cablecast went away, this site would lose the programme catalogue, the
archive, the live stream and the airing history in a single move, and there is
no second source for any of it.** Nothing else on the dependency list comes
close to that. Nothing in this round touched Cablecast.

## What moved this round

The deploy landscape — the part of my brief that overlaps the constitution's
"worth a board conversation on its own" line — changed more this round than
anything else has since seating.

**Cloudflare's own git-connected builder broke.** It began reporting this
repository as *damaged* and stopped deploying. Recreating the Cloudflare
project fixed it. The cause is a documented hypothesis — a submodule pin
(`.advocate-engine`, mounted 2026-09-04) that a shallow clone cannot resolve —
not a confirmed one.

**The response was a third deploy path**, not a fix to the second: GitHub
Actions now runs `wrangler deploy` directly, gated on an org secret
(`CLOUDFLARE_PAGES_TOKEN`) that is not set by default. Unlike the Azure path at
seating, this one arrived **with its either/or written down in the same
commit**: "Set that secret while the git connection is live and both will
publish the same site... Whichever you pick, turn the other off in the same
sitting." That is exactly the shape A2 asks for — for *this* pair.

**The Azure path is untouched.** Still dormant, still gated on a secret that
does not exist, still explained only by a workflow's `if:` condition and by a
README section ("Cloudflare or Azure?") that has not changed since I read it
at seating and reads as settled policy rather than a current operational fact.

**A gap in this reading, stated plainly:** at seating I confirmed the Azure
step was genuinely skipped by reading the actual run history, not the workflow
file. I did not have that tool this round, so I am reporting the *documents*
and reporting that I could not re-verify the *runs* — I am not assuming
September's state still holds. Closing that gap is the first thing to do next
session.

## The concentration, in numbers rather than adjectives

`_data/cablecast.json` is 790KB and holds 1080 programmes across at least
eleven categories — 268 News, 195 Arts and Culture, 111 Fort Collins Events,
108 Fort Collins Music, and a long tail. `_data/airings.json` holds the
broadcast log, 237 aired this year. Both are generated by `sync-cablecast.yml`.
I did not re-check whether it is still succeeding this round — see the gap
above; the same tool gap applies here.

The metadata is not the archive: the video files, the live stream and the
player all live at Cablecast, and none of them is or could be in this
repository. **We would keep the card catalogue and lose the library.**

## What would make us stop

One vendor holds something irreplaceable, and what would make it stop is
commercial, not technical — an acquisition, a price change, a product sunset —
and none of that appears in a repository. A reading pass twice a year is the
right instrument for it.

This round added a second, narrower version of the same worry: **would we
notice if the way we reach a vendor broke, rather than the vendor itself?**
Cloudflare's builder stopped deploying silently — no alert reached this
repository, a person had to notice the site was stale. The new Actions path is
a spare, not a fix, and it is "unarmed": if the git connection breaks the same
way again, nothing fails over on its own. Someone still has to notice.
